# 组合管理需求与实现基线

最后更新：2026-07-18
代码基线：`main@d57d6cc`
状态：已实现、已上线

## 1. 功能定位

组合管理用于维护真实或模拟的持仓、现金、交易计划、份额和净值。模块与股池估值版本联动，但组合数据独立保存。

## 2. 页面结构

1. 组合切换和资产隐私开关。
2. 开仓、换仓、调仓建议、组合卡片、标签组和更多操作。
3. 持仓 / 净值二级导航。
4. 今日待操作。
5. 资产汇总、标签统计和持仓表格。
6. 净值曲线、基准对比和指标。

## 3. 账户和组合

| 账户 | 可用市场 | 现金 | 净值基准 |
| --- | --- | --- | --- |
| 人民币账户 | A 股、港股通 | CNY | CNY |
| 港美账户 | 港股、美股 | HKD、USD | USD |

- 创建时必填名称、账户类型和启动金额。
- 同一用户组合名称不可重复。
- 启动金额初始化现金、`startBase` 和 `totalUnits`，初始净值为 1。
- 支持初始化导入多行持仓、切换、重命名和删除。
- 删除需要二次确认。

## 4. 资产和份额口径

```text
净资产（基准币）= 持仓市值 + 现金
单位净值 = 净资产 / totalUnits
申购或赎回份额 = 原币金额折算基准币 / 操作前单位净值
```

- 申购增加现金和份额；赎回减少现金和份额。
- 赎回不得超过现金，不允许赎回全部份额。
- 现金校准直接覆盖余额，不改变份额，差额计入组合收益。
- 页面汇总金额统一折算为人民币万元；港美账户净值仍按 USD 计算。

## 5. 持仓和交易

持仓行展示股票、股数、摊薄成本、实时价、涨跌幅、当日与持仓盈亏、市值、仓位、目标仓位、估值指标、30 周乖离率、过去 2 年分位值及操作。30 周乖离率和 2 年分位值均支持列表排序。

30 周乖离率采用前复权周收盘价计算：`(最新周线收盘价 / 最近 30 周收盘价算术平均值 - 1) × 100%`。过去 2 年分位值取最近 104 个有效周度乖离率，按中秩百分位计算当前值的位置，最低为 0%、最高为 100%；不足 104 个有效观察值时不展示分位值。

股池和组合持仓页展示乖离值提醒区：乖离率低于 -30% 或分位低于 10% 为弱周期极端位置；乖离率高于 30% 或分位高于 90% 为强周期极端位置；最近 3 个周度乖离值严格递增为叙事展开期，严格递减为叙事压缩期。同一股票可以同时命中极端位置与趋势提醒。

- 开仓支持中文、代码和拼音搜索。
- 加仓重算摊薄成本并扣减现金。
- 减持增加现金，并按剩余未回收本金调整摊薄成本。
- 全部减持后删除持仓。
- 换仓同时处理卖出和买入，更新现金并写入两条交易历史。
- 卖出数量不得超过持仓；涉及买入时必须通过现金校验。

## 6. 编辑持仓和动态计划

左栏包含股票、摊薄成本、股数、当前仓位、估值版本、目标仓位和标签；右栏为加减仓计划。

- 初始至少 3 个买点和 3 个卖点。
- “添加买点 / 添加卖点”追加行并连续编号。
- 每行包含价格、Upside、Forward PE、股东回报率、股数、对应仓位和完成状态。
- 价格可正算指标，任一指标可反算价格和其余指标。
- 股数或价格变化时重算对应仓位。
- 新增行随组合 payload 保存，重开后仍存在。
- 动态数组不得假设固定只有 3 行。

## 7. 标签、目标仓位和提醒

- 持仓支持多标签、标签重命名和筛选。
- 标签可维护组合级目标仓位，并展示实际与目标偏差。
- 调仓建议通过全局约束计算统筹重叠标签、个股目标上限和现金，再结合持仓关联估值版本、买卖点与交易单位，将结果区分为“现在执行”和“等待条件”。
- 建议展示调整前后标签偏差、预计换手率、有效估值覆盖，并明确提示当前约束下无法实现的标签目标。
- 今日待操作使用当日高低价判断未完成点位是否触达。
- 触达后高亮对应加仓或减仓入口。

## 8. 净值

- 日终净值由 `daily-portfolio-nav` Edge Function 和 pg_cron 生成。
- 支持三个月、年初至今、指定年份和全部时间范围。
- 基准包括沪深300、恒生指数、恒生科技、标普500和纳指100。
- 指标包括区间收益、最大回撤和年化夏普比率。

后台对象：

- `portfolio_cash_flows`：申购赎回流水。
- `portfolio_daily_nav`：日终组合净值。
- `benchmark_daily_close`：基准收盘价。
- `daily-portfolio-nav`：抓取行情、汇率并生成日终记录。

## 9. 后台部署与验证

1. 在 Supabase 执行 `supabase/portfolio-management.sql`、`supabase/portfolio-nav.sql`。
2. 部署 `supabase/functions/daily-portfolio-nav/index.ts`。
3. 配置 `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY` 和 `CRON_SECRET`。
4. 按 `supabase/portfolio-nav-schedule.sql` 创建 pg_cron 任务。
5. 手工调用函数，确认返回成功且三张净值表写入正常。
6. 打开组合净值页，验证曲线、基准和指标。

生产密钥不得进入前端、仓库或文档；已有生产调度不应在无备份时重建。

## 10. 数据与安全

- 组合主体保存在 `portfolios.payload`，RLS 按用户隔离。
- `tradeHistory[]`、标签、目标仓位和买卖点是嵌套数据。
- position `id` 是持仓真实标识，`code + market` 只用于兼容。
- 演示模式使用 Local Storage，不写生产库。
- 资产隐私开关只负责展示隐藏，不替代数据权限。

## 11. 已知限制

- 交易未完整建模佣金、税费、分红、利息和换汇。
- 现金校准没有独立审计流水。
- 动态计划尚无单行删除和排序。
- 净值没有自动历史回填。
- 组合暂不支持公开分享。

## 12. 回归验收

- [ ] 开仓、加仓、减持和调仓后持仓与现金正确。
- [ ] 申购赎回前后净值不异常跳变。
- [ ] 估值预览和所有动态计划行指标正常。
- [ ] 旧股票缺少 `quoteId` 时仍能刷新市值。
- [ ] 新增第 4 个买点 / 卖点后保存和重开正常。
- [ ] 待操作、提醒点和完成状态一致。
- [ ] 隐私模式不泄露资产数字。
- [ ] 日终任务、曲线和基准数据正常。
