## 3. 产品与计算规则

### 3.1 账户基准货币

| 账户类型 | 可交易市场 | 现金币种 | 净值基准币种 | 持仓列表市值 |
| --- | --- | --- | --- | --- |
| 人民币账户 | A 股 | CNY | CNY | 人民币万元 |
| 港美账户 | 港股、美股 | HKD、USD | USD | 美元 |

汇总区的净资产、仓位市值和现金市值统一折算成人民币，以“万元”展示并保留到整数。港美账户的份额净值仍按美元基准计算。

### 3.2 启动金额和初始份额

创建组合时金额输入单位为“万元”：

- 人民币账户输入人民币万元；
- 港美账户分别输入万港币和万美元。

保存时乘以 10,000 转为原币金额。创建组合时：

```text
人民币账户 startBase = CNY 启动金额
港美账户 startBase = USD 启动金额 + HKD 启动金额 × HKD/USD
totalUnits = startBase
初始单位净值 = 1.0000
```

`startBase` 用于兼容和初始化，净值运行后不再以启动金额作为固定分母。

### 3.3 盘中估算净值

```text
净资产（基准币） = 持仓市值（基准币） + 现金（基准币）
盘中估算净值 = 净资产（基准币） / totalUnits
```

页面打开组合管理时刷新行情。行情不可用时，代码按“最新价 → 摊薄成本”逐级兜底，因此盘中净值是估值，不是清算结果。

### 3.4 申购和赎回

申购、赎回均按操作前盘中净值折算份额：

```text
基准币金额 = 原币金额 × 原币/基准币汇率
变更份额 = 基准币金额 / 操作前单位净值
```

- 申购：现金增加，`totalUnits` 增加；
- 赎回：现金减少，`totalUnits` 减少；
- 赎回受对应币种现金余额约束；
- 当前实现不允许赎回全部份额；
- 操作同时写入组合 payload 和 `portfolio_cash_flows`。

正常情况下，申购和赎回不会令单位净值跳变。

### 3.5 现金校准

现金校准用于吸收佣金、税费、分红等未独立记账的差异：

- 直接覆盖当前现金余额；
- 不改变 `totalUnits`；
- 因此差额会进入组合收益，改变单位净值；
- 当前没有单独保存校准流水及原因。

### 3.6 开仓、加仓、减持和交易历史

交易按股票原始币种结算：A 股 CNY、港股 HKD、美股 USD。

```text
加仓后摊薄成本 =
(原股数 × 原摊薄成本 + 买入股数 × 买入价) / 新股数

减持后摊薄成本 =
(原股数 × 原摊薄成本 - 卖出股数 × 卖出价) / 剩余股数
```

减持使用“剩余未回收本金”口径，因此高价减持会降低摊薄成本，累计回收超过投入后摊薄成本允许为负数。全部减持时删除该持仓。

当前交易历史保存在组合 payload 的 `tradeHistory[]` 中：

- 加仓写入一条 `add` 记录；
- 减持写入一条 `reduce` 记录；
- 调仓写入两条记录：卖出侧 `reduce`、买入侧 `add`；
- 开仓当前不写入交易历史；
- 交易历史按持仓查看，展示日期、交易类型、成交价和变动股数。

### 3.7 调仓助手

入口位于组合管理操作行，与“申购”“赎回”“开仓”同一行。

调仓助手当前实现：

- 浮层左右横向展示卖出区和买入区；
- 卖出股票和买入股票均复用开仓股票搜索；
- 选择股票后自动带入实时价，价格允许手动修改；
- 卖出股票必须是当前持仓，买入股票可为已有持仓或新股票；
- 卖出/买入价格与数量同一行，字段宽度收窄；
- 每侧股票名称、数量输入框和后仓位卡片右侧边界对齐；
- 数量下方提供 `1/5`、`1/4`、`1/3`、`1/2` 快捷比例；
- 输入卖出或买入数量时，另一侧数量按交易金额、汇率和基准币折算自动估算；
- 仓位预览展示当前持仓仓位、本次交易仓位和交易后仓位。

点击“确认调仓”后，前端在一次 `updateActivePortfolio` 中同时更新：

- 卖出侧股数、摊薄成本和现金；
- 买入侧股数、摊薄成本或新持仓；
- 组合现金；
- 两条交易历史记录。

调仓没有独立数据库表，也没有单独一条“调仓流水”；当前以两条买卖记录表达。

## 4. 日终净值机制

### 4.1 执行链路

```text
pg_cron
  → pg_net HTTP POST
  → daily-portfolio-nav Edge Function
  → 读取 portfolios.payload
  → 获取股票、指数行情及汇率
  → 写入 portfolio_daily_nav
  → 写入 benchmark_daily_close
```

定时任务每天 UTC 23:30 执行，即北京时间次日 07:30。该时间覆盖美股夏令时和冬令时常规收盘，用户无需打开网页。

### 4.2 日期口径

- 人民币账户优先采用 A 股持仓行情交易日；
- 港美账户优先采用美股、港股持仓行情交易日中的最新日期；
- 无对应持仓行情日期时，按账户时区取得自然日兜底；
- 同一组合、同一 `nav_date` 重复执行时使用 upsert 覆盖，不产生重复记录。

### 4.3 行情与汇率来源

- 股票和基准指数：腾讯行情接口；
- 外汇：Open ER API；
- 快照记录 `generated_at`、行情来源和使用到的交易日期；
- 行情失败时，持仓价格回退至 payload 中的 `latestPrice`，再回退至 `averageCost`。

### 4.4 基准指数

| 代码 | 展示名称 | 行情符号 | 适用账户 |
| --- | --- | --- | --- |
| CSI300 | 沪深300 | sh000300 | 人民币账户 |
| HSI | 恒生指数 | hkHSI | 港美账户 |
| HSTECH | 恒生科技 | hkHSTECH | 港美账户 |
| SP500 | 标普500 | usINX | 港美账户 |
| NDX100 | 纳斯达克100 | usNDX | 港美账户 |

当前仅从上线日起逐日积累，不自动回填历史行情。

## 5. 净值曲线和指标

页面支持：

- 最近三个月；
- 年初至今；
- 指定年份；
- 全部；
- 组合与所选基准归一化曲线比较。

计算规则：

```text
区间收益 = 区间末单位净值 / 区间初单位净值 - 1
最大回撤 = min(当日净值 / 历史峰值 - 1)
年化夏普 = 日收益均值 / 日收益样本标准差 × √252
```

当前夏普比率的无风险利率按 0 处理。少于两个日终净值点时，曲线和统计指标不展示有效结果。

## 6. 数据模型

### 6.1 `public.portfolios`

每个组合一行，核心业务对象暂存在 `payload jsonb`：

- `name`、`accountType`；
- `startCny`、`startHkd`、`startUsd`、`startBase`；
- `totalUnits`；
- `cash.CNY/HKD/USD`；
- `positions[]`；
- `cashFlows[]`；
- `tradeHistory[]`；
- 创建、更新时间。

前端每次变更后将组合整体 upsert 到 Supabase，同时保留用户维度 localStorage 缓存。首次启用云端且云端为空时，会迁移本地组合。

### 6.2 `public.portfolio_cash_flows`

保存申购、赎回流水，主要字段：组合、用户、类型、币种、金额、操作前净值、变更份额、发生时间。

### 6.3 `public.portfolio_daily_nav`

以 `(portfolio_id, nav_date)` 为主键，保存：基准币种、总资产、总份额、单位净值、现金、仓位、汇率和价格状态。

### 6.4 `public.benchmark_daily_close`

以 `(benchmark_code, trade_date)` 为主键，保存基准代码、交易日、收盘值、币种和来源。

### 6.5 权限

- 用户通过 RLS 只能管理自己的组合和现金流、读取自己的净值；
- 登录用户可读取公共基准数据；
- Edge Function 使用 `service_role` 读取组合并写入净值、基准表；
- 函数 HTTP 入口必须携带正确的 `x-cron-secret`。

## 8. 运维与故障排查

### 8.1 每日检查

正常运行后不需要人工操作。需要抽查时：

1. Edge Functions → `daily-portfolio-nav` → Invocations，确认每日出现 200；
2. 查看 `portfolio_daily_nav` 是否增加对应交易日记录；
3. 查看 `benchmark_daily_close` 是否持续增加；
4. 线上进入“组合管理 → 净值曲线”确认数据可读取。

### 8.2 常见错误

- 401：`CRON_SECRET` 与 Vault 中的调度密钥不一致，或 JWT 校验被重新打开；
- 500 / permission denied：检查 `service_role` 对三张目标表的权限；
- 净值没有新日期：检查行情返回日期、Edge Function 日志和 cron 执行记录；
- 曲线为空：确认至少有两个净值点，且当前用户有对应组合的净值数据；
- 基准不显示：组合净值日期和基准交易日没有可对齐的数据点。

### 8.3 安全约束

- 不在 Git、文档、日志或前端代码中保存 `CRON_SECRET`；
- 不在前端暴露 `SUPABASE_SERVICE_ROLE_KEY`；
- 轮换 cron 密钥时必须同时更新 Edge Function Secret 和 Vault Secret；
- 删除组合会通过外键级联删除现金流水和日终净值。

## 9. 当前已知限制

以下不是本轮遗留故障，而是后续可演进项：

- 前端仍为单文件 `index.html`，组合对象整体以 JSONB 保存；
- 加仓、减持和调仓交易历史仍保存在组合 payload 中，尚未拆成独立交易表；
- 开仓当前不写入交易历史；
- 未单独核算佣金、税费、分红、利息和换汇；
- 现金校准没有原因和审计记录；
- 没有历史净值和指数数据回填；
- 夏普比率无风险利率固定为 0，且未处理非连续交易日的精细年化；
- 港股、美股不同休市日只通过可取得的最新行情日期对齐；
- 腾讯行情和免费汇率接口没有 SLA；
- 当前没有定时任务失败告警、重试看板和数据质量告警；
- 多设备同时编辑同一组合采用最后写入覆盖，没有乐观锁或冲突合并；
- 当前自动任务每天生成一次，不保存盘中净值时间序列。
